# Сайт-портфолио: цели и план реализации

Oct 20, 2026 · @Iakov

## Цели

Сайт за 30 секунд показывает рекрутеру, кто я и что я ищу, а техлиду — что я умею строить и сопровождать продакшен-бэкенд на .NET. Главное доказательство — сам сайт: он работает на заявленном стеке, код открыт, мониторинг виден всем.

| Цель | Как измеряем | Цель MVP |
| --- | --- | --- |
| Понятно за 30 секунд | Имя, роль, статус и контакт видны на первом экране без кликов | 100% экранов от 1280 px и мобильных |
| Быстро открывается | LCP на десктопе, 4G | < 2,5 с; 3D-сцена интерактивна < 4 с |
| Доступность и качество | Lighthouse Performance / Accessibility | ≥ 85 / ≥ 95 |
| Сайт как доказательство навыков | Сервисы на .NET, Kafka, SignalR, OpenTelemetry работают в продакшене | Все 5 сервисов живые, трейс клика виден от браузера до SignalR |
| Надёжность | Uptime за 30 дней, внешняя проверка | ≥ 99,5% |
| Открытый чистый код | Запуск локально одной командой, CI зелёный, тесты в каждом сервисе | Да |
| Конверсия в контакт | Доля визитов с кликом по Contact, CV, Telegram, GitHub, hh | Базовая линия за первый месяц, потом цель |

## Объём MVP

MVP — это текущий концепт, перенесённый в живой код, плюс бэкенд и мониторинг. Всё, что не влияет на первые 30 секунд или на доказательство стека, идёт после.

**Входит в MVP**

- Одностраничная карта-остров: 6 остановок по порядку чтения резюме, грузовик, клик по зданию, поворот карты.
- Окна глав: Profile, ProSpace, TimePath, Tech stack (серверная), Education, Contact, 30-sec summary, Monitoring.
- Нижняя панель: профиль, маршрут, CTA.
- Три палитры: день, вечер, ночь. Два языка: EN и RU.
- Резервный режим без 3D для слабых устройств и мобильных.
- 5 сервисов на .NET, Kafka как журнал событий, SignalR для живых данных, PostgreSQL.
- Полный мониторинг: логи, метрики, трейсы, алерты, публичное окно Monitoring.
- CI/CD, домен, HTTPS, открытый репозиторий с README и схемой.

**Сознательно после MVP**

- Свои модели из Blender. В MVP здания собираются из примитивов, как в концепте, модели подменяются без переделки кода.
- The Lab, блог, админка для контента.
- Kubernetes (k3s) и масштабирование в несколько инстансов.
- Финальный дизайн: он будет переделываться, поэтому контент, сцена и стили окон держим раздельно.

## Архитектура

Браузер ходит только в gateway. Каждое действие посетителя пишется один раз в журнал Kafka, дальше его независимо читают два потребителя.

## Фронтенд

Vue 3 + TypeScript + Vite, 3D на TresJS. Окна и панель — обычный HTML поверх сцены, а не 3D: так текст чёткий, доступен с клавиатуры и виден поисковикам.

| Часть | Решение |
| --- | --- |
| Состояние | Pinia: активная остановка, открытое окно, тема, язык, поворот карты |
| Сцена | TresJS + cientos, ортографическая камера в изометрии, поворот шагом 90° |
| Здания | Ключевые — отдельные компоненты, фоновые — InstancedMesh. Потом замена на glTF из Blender |
| Грузовик | Движение по путевым точкам в цикле рендера, курс через atan2, как в концепте |
| Темы | Цвета материалов, свет и вода берутся из одного объекта палитры; те же токены идут в CSS-переменные |
| Языки | vue-i18n, EN по умолчанию, RU по языку браузера и переключателю |
| Контент | Из Content API; на сборке вшивается снимок JSON на случай недоступности API |
| SEO и без JS | Предрендер текста всех глав в HTML (vite-ssg), Open Graph для превью ссылки |
| Резерв | Нет WebGL, слабое устройство или телефон → статичная картинка карты + список остановок, окна на весь экран |
| Доступность | Всё доступно из нижней панели с клавиатуры, окна — диалоги с фокусом, учёт prefers-reduced-motion |

Бюджет производительности: первый экран — только HTML панели и картинка-заглушка карты, JS без 3D ≤ 150 КБ gzip. Сцена подгружается после первой отрисовки, её ассеты ≤ 2 МБ.

## Бэкенд

Пять небольших сервисов на .NET 10, каждый с одной ответственностью. Логика не дублирует прошлые проекты: сервисы обслуживают сам сайт — контент, события посетителей, живую статистику.

| Сервис | Что делает | Какой навык показывает |
| --- | --- | --- |
| gateway | Единая точка входа на YARP: маршруты, rate limiting, CORS | ASP.NET Core, защита публичного API |
| content-api | Главы, навыки, ссылки на EN/RU. Данные в PostgreSQL, сид из JSON в репозитории, output cache + ETag | EF Core, PostgreSQL, кэширование |
| events-api | Принимает события из браузера, валидирует, обезличивает, пишет в Kafka | Kafka producer, идемпотентность |
| projector | Читает журнал и строит агрегаты в PostgreSQL: визиты по дням, популярные главы, клики по CTA | Kafka consumer, проекции, идемпотентная обработка по eventId |
| live-hub | Вторая consumer group того же топика → SignalR: посетители онлайн, лента событий, метрики для окна Monitoring | SignalR, fan-out одного журнала в два потребителя |

**Событие в журнале.** Топик `site.events.v1`, ключ — sessionId. Поля: `eventId` (UUIDv7), `type` (visit, stop\_opened, skill\_opened, cta\_click, web\_vital), `occurredAt`, `sessionId`, `lang`, `theme`, `payload`. Схема версионируется, контракты лежат в общем проекте Contracts.

**Приватность.** IP не хранится, sessionId — хэш с солью, которая меняется раз в сутки. Без cookies и сторонней аналитики, поэтому баннер согласия не нужен.

**Общее для всех сервисов.** Minimal APIs, ServiceDefaults из Aspire (OpenTelemetry, health checks, resilience), `/health` и `/alive`, конфигурация через переменные окружения. Локально всё поднимает Aspire AppHost, в продакшене — Docker Compose.

## Мониторинг

Мониторинг — часть витрины: строим его как в продакшене и часть показываем посетителям. Стек: OpenTelemetry → Collector → Prometheus (метрики), Loki (логи), Tempo (трейсы) → Grafana.

- **Трейсы через Kafka.** Контекст трейса едет в заголовках сообщения, поэтому один клик виден целиком: браузер → gateway → events-api → Kafka → projector и live-hub → SignalR.
- **Метрики.** RED по каждому сервису (запросы, ошибки, длительность), consumer lag, подключения SignalR, бизнес-метрики сайта (визиты, открытые главы, клики по CTA).
- **Фронтенд.** Web Vitals (LCP, INP, CLS) уходят событиями в events-api и становятся метриками.
- **Публичное окно Monitoring.** Данные отдаёт live-hub: онлайн, запросы в минуту, p95, доля ошибок, consumer lag, uptime. Он сам опрашивает Prometheus и кэширует на 10 с. Prometheus и Grafana наружу не открываем.
- **Алерты в Telegram.** Сервис не отвечает, ошибки > 2% за 5 минут, растёт consumer lag, диск > 80%.
- **Внешний uptime.** Бесплатный внешний пинг раз в минуту, чтобы видеть падение всего сервера.
- **Дашборды как код.** JSON дашбордов и правила алертов лежат в репозитории и поднимаются провиженингом.

## Инфраструктура и бюджет

Один VPS на 4 vCPU / 8 ГБ с Docker Compose, фронтенд статикой на бесплатном CDN. Без Azure и без управляемых облачных сервисов. 8 ГБ нужны из-за Kafka и стека мониторинга, сами сервисы лёгкие.

| Статья | Вариант | Стоимость |
| --- | --- | --- |
| Сервер | VPS 4 vCPU / 8 ГБ в ЕС: Hetzner, Netcup или аналог | €10–36 в месяц, цены выросли в 2026, нужно сравнить перед покупкой ([источник](https://findstack.com/resources/hetzner-price-increase-2026)) |
| Фронтенд | Cloudflare Pages или GitHub Pages | бесплатно |
| Домен | .dev или .com | ≈ €10–15 в год |
| HTTPS и прокси | Caddy с автоматическим Let's Encrypt | бесплатно |
| CI/CD и образы | GitHub Actions + GHCR для публичного репозитория | бесплатно |
| Внешний uptime | бесплатный тариф UptimeRobot или аналога | бесплатно |
| Бэкапы | ночной pg\_dump в дешёвое объектное хранилище | ≈ €1 в месяц |

**Деплой.** Тег `v*` в main → GitHub Actions собирает и тестирует → образы в GHCR → по SSH `docker compose pull && up -d` на сервере → smoke-тест `/health`. Секреты только в GitHub Secrets и `.env` на сервере.

**Если сервер дорогой.** Метрики, логи и трейсы уводим в бесплатный тариф Grafana Cloud, тогда хватит VPS на 4 ГБ.

## Репозиторий и качество кода

Один публичный монорепозиторий на github.com/pollezha. Техлид должен за 5 минут понять устройство по README и запустить всё одной командой.

```
/frontend            Vue 3 + TresJS
/services
  /gateway           YARP
  /content-api
  /events-api
  /projector
  /live-hub
/src/Contracts       схемы событий и DTO
/src/ServiceDefaults OpenTelemetry, health, resilience
/src/AppHost         Aspire для локального запуска
/tests               unit + integration (Testcontainers)
/deploy              compose, Caddy, OTel Collector, Grafana
/docs                схема архитектуры, ADR
CLAUDE.md            правила для AI-агента
```

- **Стиль и анализаторы.** .editorconfig, Nullable включён, TreatWarningsAsErrors, `dotnet format` в CI. На фронтенде ESLint + Prettier + vue-tsc.
- **Тесты.** xUnit на логику, Testcontainers для Kafka и PostgreSQL, Vitest для сторов, Playwright smoke: сайт открылся → грузовик доехал → окно показалось.
- **История.** Conventional Commits, PR на каждую итерацию даже в одиночку, CHANGELOG по тегам.
- **Решения.** Короткие ADR: почему Kafka, почему две consumer group, почему HTML-окна поверх 3D.
- **Разработка с агентом.** CLAUDE.md, набор команд и правил лежат в репозитории. Это живое подтверждение навыка Agent setup из серверной.

## Риски и открытые вопросы

Главный риск — не уложиться в 2 недели. Порядок этапов выбран так, чтобы после каждого у вас был работающий сайт.

| Риск | Что делаем |
| --- | --- |
| 5 сервисов + мониторинг не влезают в срок | Сначала сайт на статическом JSON, бэкенд подключается потом; при нехватке времени projector и live-hub объединяются |
| 3D тормозит на слабых ноутбуках и телефонах | Резервный 2D-режим, ленивая загрузка сцены, InstancedMesh, бюджеты в CI |
| Kafka и мониторинг съедают память сервера | Kafka в режиме KRaft с ограниченным heap, лимиты памяти на контейнеры, запасной вариант — Grafana Cloud |
| Спам событиями в публичный API | Rate limit в gateway, валидация схемы, фильтр ботов по User-Agent |
| Дизайн будет переделываться | Контент — данные, сцена и стили окон — отдельные слои |
| Модели в Blender съедают время | В MVP примитивы, модели после запуска |
