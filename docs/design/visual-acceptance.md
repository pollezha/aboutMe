# Визуальная приёмка: код идёт от дизайна

Принято 2026-10-25 после разбора этапа 3: 3D-остров ушёл на прод непохожим на Figma, потому что задачи
принимались по тестам, а не по виду. Цель — максимальное попадание в ожидания: то, что в Figma, то и на сайте.

## Правила
1. **Источник истины — Figma** (`1D6lW84rl4yYR8VQwV10Pp`, ID узлов — `docs/design/figma-state.json`). Код
   повторяет макет; любое отличие — либо баг кода, либо решение пользователя, записанное в спеке модуля.
2. **Нет эталона — нет задачи.** Если для элемента в Figma нет макета (заглушка, концепт-арт, «reference PNG»)
   или макет противоречит плану, задача не стартует: оркестратор спрашивает пользователя — дорисовать в Figma
   или считать эталоном то, что есть.
3. **Ничего не потеряно и не добавлено сверх задачи.** Каждый элемент макета есть на сайте; на сайте нет
   элементов, которых нет в макете или в задаче.
4. **Приёмка UI-задачи — только с картинками.** Без пары «Figma ↔ сайт» в тех же размерах задача не принята,
   сколько бы тестов ни было зелёными.
5. **Оркестратор смотрит картинки сам** (правило «не читать исходники» на них не распространяется) и показывает
   пользователю промежуточные визуальные вехи, не дожидаясь конца этапа.
6. **Замечания о внешнем виде из отчётов — вопрос к пользователю, а не «не блокер».**

## Процедура (каждая задача, которая меняет то, что видно)
1. **Эталон.** Оркестратор до старта снимает кадры фреймов Figma задачи (`get_screenshot`, натуральный размер)
   в `docs/design/figma-screens/<frame>.png` и передаёт исполнителю ID узлов и пути к кадрам. Исполнитель Figma
   не открывает.
2. **Кадр сайта.** Исполнитель снимает сайт в тех же размерах и состоянии (тема, язык, режим 2D/3D, открытое окно,
   `prefers-reduced-motion: reduce`) в `docs/design/compare/<task>/<frame>.site.png`, рядом копирует эталон
   `<frame>.figma.png`.
3. **Сверка по чек-листу** (ниже) — исполнитель в отчёте, затем сабагент `design-reviewer` в чистом контексте.
4. **Решение.** Оркестратор открывает обе картинки. Расхождение — либо фикс в той же задаче, либо вопрос
   пользователю, либо запись в спеке модуля «отличается от Figma, потому что…» с решением пользователя.
5. **Веха.** Новый экран, сцена, окно, крупный элемент — кадр пользователю до перехода к следующей задаче.

## Чек-лист сверки
| Что | Как проверить |
|---|---|
| Состав | Каждый элемент макета на месте; лишних элементов нет; число пунктов, кнопок, пинов совпадает |
| Расположение | Порядок и выравнивание; отступы по токенам `--space-*`; положение относительно соседей и краёв кадра |
| Размеры | Ширина/высота блоков, кнопок (44/48), иконок (18/20/24), радиусы `--radius-*` |
| Цвет | Только токены; совпадает роль токена (surface / surface-alt / accent / chapter-*); в 3 темах |
| Типографика | Text style Figma = класс `.t-*`; регистр (капс/строчные), вес, размер, межстрочный |
| Тексты | Совпадают с макетом или с контентом, на который макет ссылается; RU не обрезан, переносится |
| Состояния | default / hover / focus / active / visited / disabled / selected — как в компоненте Figma |
| Иконки и знаки | Тот же значок, тот же цвет и размер |
| Адаптив | Те же фреймы: 1440, 1280, 768, 390 — что макет показывает на каждом |
| 3D/иллюстрация | Расстановка объектов, ракурс, силуэты, палитра, подписи/пины — как в эталонном кадре |

Отчёт сверки — таблица `элемент | Figma | сайт | вердикт (совпадает / расходится / решение пользователя)`.

## Где что лежит
- Эталонные кадры: `docs/design/figma-screens/` (обновляет оркестратор при изменении Figma).
- Пары для задачи: `docs/design/compare/<task>/` (коммитятся вместе с задачей — это доказательство приёмки).
- Решения «отличается от Figma» и нюансы — в спеке модуля `docs/spec/frontend/<module>.md`.
