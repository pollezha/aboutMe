# Уроки проекта

Пополняется скиллом `/learn`. Формат записи:

```
## YYYY-MM-DD — <коротко>
- Что случилось: <...>
- Причина: <...>
- Правило на будущее: <...>
- Куда закреплено: CLAUDE.md | REVIEW.md | тест | линтер | скилл <имя>
```

Если урок повторился дважды — он должен быть закреплён механически (тест, линтер, хук), а не только текстом.

Закреплённые механически уроки этапов 1–2 — в `docs/learnings-archive.md`. На шлюзе этапа переносить туда
записи, у которых «Куда закреплено» — тест, линтер, CI или конфиг.

## 2026-10-21 — этап 1: процесс ревью и оркестрации
- Что случилось: 4 reviewer дали 13 находок, verifier снизил severity у 9 и отклонил 2 — ревьюеры
  систематически завышают severity («major» без достижимого сценария: офлайн-фид VS не даёт NU1507, TC-10 не
  про ошибки схемы). Два implementer параллельно в одной рабочей копии — сработало, но каждый видел чужие
  незакоммиченные файлы и тратил контекст на предупреждения об этом. Сломанный хук блокирует Edit/Write
  на всё, включая сам хук, — чинить пришлось через node.
- Правило на будущее: verifier обязателен всегда (он окупился); параллельные implementer — только в
  worktree (как и записано в /implement); правку хука делать так: сначала тест в `.test.js`, потом код,
  `node --test` до коммита.
- Куда закреплено: REVIEW.md (severity без сценария → не major), /implement (worktree), тесты хука.

## 2026-10-23 — этап 3, T1: схема контента глав
- Что случилось: ajv в strict-режиме отказывается компилировать схему, где внутри `if/then` в `required` стоит
  свойство, не объявленное в `properties` того же подсхемы (strictRequired); в `scripts/` (tsconfig.node,
  lib ES2023, `types: []`) нет `structuredClone`.
- Урок: в условных подсхемах объявлять `properties` рядом с `required`; для глубокого копирования в скриптах —
  `JSON.parse(JSON.stringify())`. Даты в контенте — токены `{since}`/`{period}`/`{experience}`, которые
  подставляет код из `experience[]` (валидатор отклоняет неизвестные токены), а не готовые строки.

## 2026-10-23 — этап 3, T7: spike сцены TresJS
- Что случилось: TresJS v5 не пересчитывает фрустум ортокамеры при ресайзе (только aspect перспективной) —
  left/right считаем от `useTres().sizes.aspectRatio`. У size-limit 14 при `gzip: false` включается brotli — для
  raw-размера нужен ещё `brotli: false`. В `scene-layout.json` у плит/дорог `h` — глубина на плоскости, у зданий —
  высота (плита сначала отрисовалась кубом). Тестам с fake timers нужен `await nextTick()` после mount.
- Урок: бюджеты держать в `postbuild` (size-limit), чтобы `npm run build` падал сам; тест по
  `dist/.vite/manifest.json` гарантирует, что three живёт только в ленивом чанке. Результат spike: main 61 КБ gzip,
  сцена 858 КБ raw — откат на чистый three не нужен.

## 2026-10-23 — этап 3, T2: окна и слияние параллельных задач
- Что случилось: HTML-комментарий внутри `<template>` превращает однокорневой SFC во фрагмент — теряются классы
  и fallthrough-атрибуты; комментарии ставить перед `<template>`. Параллельные T2 и T7 оба правили
  `App.spec.ts` → конфликт в `afterEach` (разрешён объединением блоков).
- Урок: задачи одной волны не должны делить тестовый файл `App.spec.ts` — новые сценарии App класть в
  отдельные spec-файлы (`App.windows.spec.ts`, `App.scene.spec.ts`). Даты в контенте считаются от `now` —
  перед T5 (vite-ssg) зафиксировать `now` сборки, иначе hydration mismatch по месяцу.

## 2026-10-23 — этап 3, T8: сцена, клик и поворот
- Что случилось: функции-свойства three (`raycast`, `lookAt`) TresJS вызывает, а не присваивает — `:raycast="fn"`
  луч не отключит; кадр под Hero проще сдвигать асимметричным фрустумом (экранный сдвиг не зависит от поворота).
  Ночью крыши (смесь с `bg/surface`) и фоновые домики выходят почти чёрными — нужны отдельные `scene/*` токены
  для ночных материалов (дизайн-пункт, не блокер).
- Урок: InstancedMesh + один материал на цвет держат ~53 draw calls и ~130 FPS на встроенной графике; FPS и
  клики проверять скриптом CDP, а не на глаз.

## 2026-10-23 — этап 4, T0: spike Kafka в Testcontainers + trace context в заголовках
- Что случилось: проброс заработал с первого прогона — consume-спан получает `TraceId` запроса и `ParentSpanId`
  спана produce; сообщение без заголовков даёт новый корневой трейс. Образ `apache/kafka:4.1.1` (KRaft, без
  ZooKeeper), `Testcontainers.Kafka` 4.16.0 (`new KafkaBuilder(image)`, вендор по имени образа), `Confluent.Kafka`
  2.16.0. Старт: ryuk ~2 с + Kafka ~5–6 с (≈ 8 с на класс), прогон 10 тестов ServiceDefaults ≈ 19 с при скачанном
  образе (первый `docker pull` — отдельно).
- Подводные камни: `Propagators.DefaultTextMapPropagator` без OpenTelemetry SDK — no-op (заголовки молча не
  пишутся); его ставит SDK при сборке `TracerProvider` — в тестах нужен `Sdk.CreateTracerProviderBuilder()`, в
  сервисах это делает `AddServiceDefaults()`. `ActivitySource.StartActivity` без слушателя возвращает null — код
  обёртки и сервисов должен это терпеть. Слушатели глобальны в процессе: тесты, создающие `TracerProvider`, —
  в одной коллекции xUnit без параллелизма. Консьюмер с новой group и дефолтным `auto.offset.reset=latest` не
  видит уже отправленное — `KafkaDefaults` ставит `Earliest`; топик в тесте создавать `AdminClient`-ом до
  подписки. `delivery.timeout.ms` в Confluent.Kafka — свойство `MessageTimeoutMs` (синоним в librdkafka).
  Новый корень без заголовков — только если цикл консьюмера не идёт внутри чужого `Activity.Current`.
- Правило на будущее: продюсер и консьюмеры пишут/читают trace context только через
  `ServiceDefaults.Kafka.KafkaTracePropagation`, конфиг — через `KafkaDefaults.Apply*`/`Create*`.
- Куда закреплено: тест (`tests/ServiceDefaults.Tests/KafkaTracePropagationTests.cs`,
  `KafkaTelemetryRegistrationTests.cs`).

## 2026-10-24 — этап 4, T2–T6, T9: сервисы на Aspire-интеграциях
- Что случилось: Aspire.Confluent.Kafka сам трассирует продюсер/консьюмер и дублирует спаны поверх обёртки

## 2026-10-24 — этап 4, R3–R7: переезд сервисов на раскладку ADR-0007
- Что случилось: Aspire `AddNpgsqlDbContext` включает `NpgsqlRetryingExecutionStrategy`, и операции EF внутри транзакции
  `EfUnitOfWork` падают «does not support user-initiated transactions» — в projector `settings.DisableRetry = true`
  (повторы делает `KafkaConsumerLoop`); тесты `EfUnitOfWork` в BuildingBlocks этого не ловили (обычный `AddDbContext`).
  Процессоры OTel для спанов (редакция токена) должны регистрироваться до `AddServiceDefaults`, иначе встанут после
  экспортёра — в ADR-0007 добавлен шаг `Add<Svc>SpanRedaction()` первым. `<Feature>Handler` для фичи на `…Event`
  ловит CA1711. В Web SDK свои `CorsOptions`/`ForwardedHeadersOptions` конфликтуют с типами ASP.NET — алиасы или другие имена.
  Хук защиты в worktree не пропускает составные bash-команды и `sed` по glob — по одной команде с явными путями.
- Урок: при переезде «без изменения поведения» существующие интеграционные тесты держат поведение, а новые юнит-тесты
  хендлеров на фейках (без Docker) — это и есть выигрыш слоёв: 40+ новых тестов идут секунды.
- Куда закреплено: ADR-0007 (порядок регистрации, именование), R8 (DisableRetry для content-api, правила слоёв тестом).
