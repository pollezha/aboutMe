# Спецификация (ТЗ): сайт-портфолио, MVP

Статус: approved · Дата: 2026-10-20
Источник: docs/concept/plan.md, docs/concept/mockup-route-city-v5.html, разбор дизайна — docs/concept/design-review.md.
План работ: docs/plans/roadmap.md. Технический дизайн: docs/design/architecture.md, ADR: docs/adr/.

## Проблема
Рекрутер тратит на кандидата 30 секунд и уходит, если не понял, кто это и как связаться. Техлиду нужен
не список технологий, а доказательство, что кандидат умеет строить и сопровождать продакшен-бэкенд на .NET.
Резюме на hh.ru и PDF этого не показывают. Сайт должен решить обе задачи: быстро ответить рекрутеру
и дать техлиду живую систему, код и мониторинг, которые можно проверить.

## Пользователи и сценарии
1. **Рекрутер (EN/RU, десктоп или телефон).** Открывает ссылку из отклика, за 30 с видит имя, роль, опыт,
   статус «open to work» и контакт; скачивает CV или пишет в Telegram.
2. **Техлид / интервьюер.** Проходит маршрут по главам (ProSpace, TimePath, стек), открывает Monitoring,
   видит живые метрики и путь клика, переходит в репозиторий, за 5 минут понимает устройство по README
   и запускает всё одной командой.
3. **Посетитель на слабом устройстве / без WebGL / с клавиатурой или скринридером.** Получает тот же
   контент в 2D-режиме, всё доступно с клавиатуры.
4. **Владелец (Яков).** Меняет тексты и навыки правкой JSON без правки кода; получает алерт в Telegram,
   если сайт упал.

## Требования

### Функциональные
- **FR1 Первый экран.** Без кликов видны: имя, роль, стаж, статус и формат (remote / relocation),
  локация, кнопки Contact и CV, ссылка на Telegram. Это HTML, не 3D.
- **FR2 Карта.** Изометрический остров с 6 остановками в порядке резюме: Profile, ProSpace, TimePath,
  Tech stack, Education, Contact. Клик по зданию или по остановке в панели открывает главу. Поворот карты
  шагом 90°.
- **FR3 Грузовик.** Едет по путевым точкам к выбранной остановке. Анимация не задерживает открытие окна
  дольше 600 мс; при prefers-reduced-motion перемещение мгновенное.
- **FR4 Нижняя панель.** Профиль, маршрут из 6 остановок с прогрессом, CTA: Contact, 30-sec summary,
  Monitoring. Переключатели темы и языка.
- **FR5 Окна глав.** 8 окон: Profile, ProSpace, TimePath, Tech stack, Education, Contact, 30-sec summary,
  Monitoring. Навигация «предыдущая / следующая» внутри окон маршрута. Закрытие по Esc и по кнопке.
- **FR6 Tech stack.** Стойки по областям, сервер = технология. Выбор сервера показывает опыт (срок,
  где применял, что делал). Опыт вычисляется из дат работы, а не хранится строкой.
- **FR7 Темы.** День, вечер, ночь. Одна палитра управляет сценой и CSS-токенами окон.
- **FR8 Языки.** EN по умолчанию, RU по языку браузера и переключателю; выбор запоминается.
- **FR9 Контент как данные.** Все тексты, навыки, ссылки, даты — в JSON (EN/RU) по схеме; сборка падает,
  если в публикуемом контенте остался `[ADD]` или ссылка `#`.
- **FR10 Резервный 2D-режим.** Нет WebGL, `deviceMemory < 4`, ширина < 768 px или явный выбор →
  статичная картинка карты + список остановок, окна на весь экран.
- **FR11 SEO и без JS.** Текст всех глав предрендерен в HTML; title, description, Open Graph-превью,
  `hreflang` для EN/RU.
- **FR12 События.** Фронт отправляет события `visit`, `stop_opened`, `skill_opened`, `cta_click`,
  `web_vital` в events-api; без cookies, без сторонней аналитики. `visit` несёт `source` из параметра
  `?src=` (hh, linkedin, tg, cv, direct) — для метрики M4.
- **FR13 Бэкенд.** 5 сервисов на .NET 10: gateway (YARP), content-api, events-api, projector, live-hub.
  Kafka-топик `site.events.v1`, две consumer group, PostgreSQL. Контракты в `src/Contracts`.
- **FR14 Окно Monitoring.** Живые данные из live-hub по SignalR: онлайн, запросы/мин, p95, доля ошибок,
  consumer lag, uptime; путь клика по реальным сервисам; ссылка на репозиторий сайта.
- **FR15 Мониторинг для владельца.** OTel → Collector → Prometheus / Loki / Tempo → Grafana; дашборды
  и алерты как код; алерты в Telegram; внешний uptime-пинг.
- **FR16 Деплой.** Тег `v*` → CI (build, test, format) → образы в GHCR → `docker compose pull && up -d`
  на VPS → smoke `/health`. Фронт — статика на CDN. HTTPS через Caddy.

### Нефункциональные
- **NFR1 Скорость.** LCP < 2,5 с (десктоп и мобильный, 4G-троттлинг); 3D интерактивна < 4 с;
  JS первого экрана без 3D ≤ 150 КБ gzip; ассеты сцены ≤ 2 МБ; шрифты ≤ 2 семейства, ≤ 150 КБ.
- **NFR2 Качество.** Lighthouse Performance ≥ 85, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95
  (мобильный профиль).
- **NFR3 Доступность.** WCAG 2.2 AA: контраст ≥ 4,5:1 для текста, фокус виден, окна — модальные
  диалоги с ловушкой фокуса и возвратом фокуса, бесконечные анимации останавливаются при
  reduced-motion и кнопкой паузы.
- **NFR4 Надёжность.** Uptime ≥ 99,5% за 30 дней. Фронт работает на вшитом снимке контента,
  если API недоступен. Падение projector не ломает live-hub и наоборот.
- **NFR5 Наблюдаемость.** Один трейс от браузера до SignalR через Kafka (контекст в заголовках
  сообщения). RED-метрики каждого сервиса, consumer lag.
- **NFR6 Приватность.** IP не хранится; sessionId — хэш с солью, меняющейся раз в сутки; нет cookies.
- **NFR7 Безопасность.** Rate limit и CORS в gateway; валидация схемы событий; Prometheus и Grafana
  наружу не открыты; секреты только в GitHub Secrets и `.env` на сервере.
- **NFR8 Ресурсы.** Весь стек помещается в VPS 4 vCPU / 8 ГБ с лимитами памяти на контейнеры.
- **NFR9 Код.** Nullable, TreatWarningsAsErrors, `dotnet format` и ESLint/Prettier/vue-tsc в CI;
  тесты в каждом сервисе; запуск локально одной командой (Aspire AppHost).

## Не входит в объём MVP
- Модели из Blender (здания из примитивов, интерфейс подмены сохраняется).
- The Lab, блог, админка контента.
- Kubernetes, несколько инстансов.
- Публичная Grafana.
- Финальная художественная проработка сцены (MVP-дизайн — по docs/concept/design-review.md).

## Критерии приёмки
- [ ] AC1: Дано окно 1280×720 и 390×844, когда страница загружена, тогда имя, роль, статус, Contact и CV
      видны без прокрутки и кликов (Playwright, скриншоты в обоих размерах и обеих темах крайних цветов).
- [ ] AC2: Дано Lighthouse CI (mobile), когда собирается PR, тогда Perf ≥ 85, A11y ≥ 95, LCP < 2,5 с,
      а бюджет JS первого экрана ≤ 150 КБ gzip — иначе CI красный.
- [ ] AC3: Дано открытая страница, когда нажат Contact в панели, тогда окно Contact открыто ≤ 600 мс
      (Playwright замер).
- [ ] AC4: Дано клавиатура, когда пройти Tab по странице, тогда достижимы все 6 остановок, CTA, тема, язык;
      окно открывается Enter, закрывается Esc, фокус возвращается на кнопку (Playwright + axe без нарушений).
- [ ] AC5: Дано браузер с RU-локалью, когда открыт сайт, тогда интерфейс и все главы на русском;
      переключатель меняет язык без перезагрузки.
- [ ] AC6: Дано отключённый WebGL (или ширина 390 px), когда открыт сайт, тогда показан 2D-режим и все 8 окон
      доступны.
- [ ] AC7: Дано JSON контента с `[ADD]` или пустой ссылкой, когда запускается сборка, тогда она падает
      с указанием поля.
- [ ] AC8: Дано событие `cta_click` из браузера, когда оно принято gateway, тогда в Tempo есть один трейс
      gateway → events-api → Kafka → projector и live-hub, агрегат в PostgreSQL увеличен ровно на 1 даже
      при повторной доставке (интеграционный тест Testcontainers + ручная проверка трейса).
- [ ] AC9: Дано открытое окно Monitoring, когда в другой вкладке открыть главу, тогда счётчик событий
      обновился ≤ 2 с без перезагрузки.
- [ ] AC10: Дано остановленный content-api, когда открыт сайт, тогда главы показываются из вшитого снимка,
      ошибок в консоли нет.
- [ ] AC11: Дано остановленный сервис или ошибки > 2% за 5 минут, когда срабатывает правило, тогда алерт
      пришёл в Telegram.
- [ ] AC12: Дано `git tag v*`, когда завершился CD, тогда на проде новая версия, smoke `/health` зелёный,
      откат на предыдущий тег — одна команда.
- [ ] AC13: Дано чистая машина с Docker и .NET 10 SDK, когда выполнить команду запуска из README,
      тогда поднимаются все сервисы и фронт. Требования к машине: Docker, .NET 10 SDK, Node.js LTS.
- [ ] AC14: Дано 30 дней в проде, тогда внешний мониторинг показывает uptime ≥ 99,5%.

## Как принимаем MVP
MVP достигнут, когда одновременно:
1. Все TC-01…TC-20 пройдены, результат приложен к PR последнего этапа (`/verify`).
2. Технические метрики T1–T5, T8–T11 в пороге на проде.
3. Продуктовые M1 и M2 в пороге — без этого сайт не считается готовым, даже если всё зелёное.
4. Через 30 дней: T7 (uptime) в пороге, по M3 и M4 есть базовая линия и выставлена цель.
