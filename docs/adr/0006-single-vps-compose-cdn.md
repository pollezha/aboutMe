# ADR-0006: Хостинг — один VPS с Docker Compose, фронт на CDN

Статус: accepted · Дата: 2026-10-20

## Контекст
Бюджет личного проекта, оплата из Сербии, один разработчик. Нужно: 5 сервисов, Kafka, PostgreSQL, OTel-стек
(NFR8: всё в 8 ГБ), uptime ≥ 99,5% (T7), деплой по тегу (FR16), без управляемых облаков (план).

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Стоимость изменения потом |
|---|---|---|---|
| A. Всё на одном VPS, включая фронт | Одна точка | Падение VPS = сайта нет; TLS и кэш статики на нас | Низкая |
| B. VPS + Compose для бэкенда, фронт на Cloudflare Pages | Сайт жив при падении VPS (снимок контента); бесплатный CDN и TLS | Два места деплоя; CORS между доменами | Низкая |
| C. k3s на VPS | Показывает Kubernetes | Больше памяти и сложности; по плану — после MVP | Средняя |
| D. Managed (Azure/AWS, Confluent Cloud) | Меньше эксплуатации | Цена, оплата из Сербии; план исключает | Высокая |

## Решение
B — единственный вариант, где отказ сервера не ломает главную цель (первые 30 секунд). Compose пишется
руками в `/deploy`, Caddy держит TLS для `api.<домен>`; миграции — отдельный шаг CD.

## Последствия
- Становится проще: дешёвый и понятный деплой; `docker compose` легко воспроизвести локально.
- Становится сложнее: один VPS — единая точка отказа бэкенда (смягчается снимком контента и внешним пингом);
  обновления ОС вручную.
- Сигнал пересмотреть: памяти не хватает (T10) → телеметрия в Grafana Cloud free и VPS на 4 ГБ;
  решение делать k3s → новый ADR.
