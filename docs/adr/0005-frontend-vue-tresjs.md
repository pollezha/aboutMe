# ADR-0005: Фронтенд — Vue 3 + Vite, 3D на TresJS

Статус: accepted · Дата: 2026-10-20

## Контекст
Нужна изометрическая сцена (остров, здания, грузовик, вода, 3 темы) и HTML-слой (ADR-0003) при бюджете
≤ 150 КБ JS на первый экран и ≤ 2 МБ на сцену (T3). Предрендер для SEO (FR11). Здания позже заменятся на
glTF из Blender.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Стоимость изменения потом |
|---|---|---|---|
| A. Vue 3 + TresJS (three.js) | Сцена как Vue-компоненты, реактивные темы из Pinia, загрузка glTF в cientos | Меньше сообщество, чем у React Three Fiber; зависимость от темпа релизов TresJS | Средняя |
| B. Vue 3 + чистый three.js | Нет прослойки, полный контроль | Императивный код сцены, ручная синхронизация состояния | Средняя |
| C. React + React Three Fiber | Самая зрелая экосистема | Отход от плана; React тяжелее в бюджете первого экрана | Высокая |
| D. Babylon.js | Мощный движок | Тяжелее three, другая экосистема | Высокая |

## Решение
A — совпадает с планом и держит сцену и UI в одной модели компонентов. Сцена изолирована в
`frontend/src/scene` и грузится динамическим импортом, поэтому переход на B при проблемах затронет только
эту папку.

## Последствия
- Становится проще: темы и состояние маршрута напрямую управляют сценой; модели Blender — подмена компонента.
- Становится сложнее: следить за совместимостью версий TresJS / cientos / three (проверить через context7 в этапе 1).
- Сигнал пересмотреть: блокирующий баг TresJS или сцена не укладывается в T2 (< 4 с) → B.
