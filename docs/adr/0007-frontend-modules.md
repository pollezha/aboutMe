# ADR-0007: Фронтенд — модули по предметным областям вместо слоёв

Статус: accepted · Дата: 2026-10-24 (одобрено пользователем)

## Контекст
`frontend/src` разложен по техническим слоям (`ui/`, `stores/`, `scene/`, `content/`, `theme/`, `i18n/`,
`fallback2d/`; design §4). Для агента с малым контекстом и для человека это обходится дорого:
- `App.vue` — 627 строк. В нём смешаны язык и маршрут `/ru/`, тема и `?theme=`, выбор 3D/2D и `?mode=`,
  загрузка сцены с таймаутом, окна и история (`#hash`, `pushState`), раскладка overlay/stacked, данные Hero,
  остановки бара, верхние контролы, предрендер текста глав. `App.spec.ts` — 709 строк, 45 тестов.
- `stores/ui.ts` (206 строк) — один стор на пять областей (тема, язык, режим/сцена, маршрут, окна). От него
  зависят окна, сцена, 2D-карта, i18n и роутер.
- Чтобы поправить «нижний бар», нужно открыть `ui/BottomBar.vue`, `ui/RouteStop.vue`, `stores/ui.ts`
  (`visitedStops`), `App.vue` (`stops`, обработчики) и `App.spec.ts`/`App.visited.spec.ts` — четыре папки.
- Границы слоёв уже проверяются (`eslint.config.js`, хелпер `boundary()`, тест
  `scripts/__tests__/layer-boundaries.spec.ts`), но они говорят «ui не знает сцену», а не «бар не знает окна».
- Ограничения: новые зависимости нельзя (никаких FSD-линтеров); three/TresJS — только в ленивом чанке сцены;
  все 8 окон — в главном чанке и в предрендере `/`, `/ru/` (vite-ssg, FR11); main ≤ 150 КБ gzip (size-limit);
  сгенерированные `src/theme/{palette.ts,tokens.css,pinInk.ts,pins.css}` и пути, на которые ссылаются
  `scripts/*.mjs` и `vite.config.ts`, без нужды не двигаем; 686 vitest + 42 e2e переживают перестройку.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Стоимость изменения потом |
|---|---|---|---|
| A. Как сейчас: слои | Ничего не делать; правила слоёв уже есть | Фича размазана по 4–5 папкам; `App.vue` и `ui.ts` растут с каждой фичей; агенту нужно читать почти всё | Растёт со временем |
| B. Модули по областям (`src/<module>/`, публичный `index.ts`) + `shared/ui`, `shared/lib`; стор — внутри своего модуля | Одна фича = одна папка + её тесты; `App.vue` — тонкий композитор; граф модулей проверяется линтером; ленивая сцена и предрендер окон — по одному правилу | Разовая миграция (18 маленьких задач); нужен граф и дисциплина «только через index»; межобластной экшен `openChapter` приходится отдать одному модулю | Низкая: модуль переезжает целиком, правила генерируются из одной таблицы |
| C. Папка на главу (`chapters/<id>/`), без общего `shared` | Глава изолирована полностью | Блоки (MetaRow в 5 окнах, MetricGrid, ChipList) и базовые компоненты дублируются или всё равно уходят в общую папку; 8 папок по одному файлу; не решает `App.vue` и стор | Средняя |
| D. B, но под `src/modules/<module>/` | Визуально отделяет модули от `app/`, `shared/` | Переезд `scene`, `content`, `theme`, `fallback2d` ломает пути в `gen-theme.mjs`, `og.mjs`, `cv.mjs`, `island.mjs`, `vite.config.ts`, `bundle.spec` (`src/scene/Scene.vue`) без пользы; длиннее импорты | Та же, что B |

Хранение состояния:
| Вариант | Плюсы | Минусы |
|---|---|---|
| S1. Один стор `ui`, как сейчас | Тесты не трогаем | Хаб, от которого зависят все модули; граф модулей теряет смысл |
| S2. Стор в своём модуле: `theme`, `locale`, `route`, `mode` | Модуль читается целиком; правка темы не задевает окна | Меняются id Pinia и импорты в тестах; `openChapter` трогает активную остановку, окно и посещённые — отдаётся `route` целиком |
| S3. Отдельный слой `state/` с файлом на область | Нет риска циклов | Область снова в двух папках — то, от чего уходим |

## Решение
B + S2: модули по предметным областям прямо в `src/<module>/`, каждый с публичным `index.ts`, сторами,
компонентами и `__tests__/` внутри; модули общаются через стор владельца или события компонентов, чужой
модуль импортируется только как `../<module>` (его `index.ts`). Главная причина: одна фича — одна папка, а граф
модулей проверяется теми же `boundary()` + тестом, без новых пакетов.

### Модули и граф зависимостей (циклы запрещены)
| Модуль | Назначение | Может импортировать |
|---|---|---|
| `shared/lib` | `useBreakpoint`, безопасный `localStorage`/`sessionStorage` | — |
| `shared/ui` | дизайн-система: BaseButton, IconButton, Icon (+ `icons/`), Dialog, StatusPill, ChapterTag, MetricCard | `shared/lib` |
| `content` | типы контента, бандлы EN/RU, главы и маршрут (`CHAPTERS`, `ROUTE`), стаж, форматирование, `BUILD_TIME` | — |
| `theme` | палитра и токены (сгенерированы), `boot.ts`, контраст, стор темы, `?theme=`, применение к `<html>` | `shared/lib` |
| `locale` | vue-i18n (`en.json`, `ru.json`), стор языка, маршруты `/` и `/ru/`, синхронизация язык ↔ маршрут | `content`, `shared/lib` |
| `route` | маршрут из 6 остановок: активная, посещённые, открытое окно (`openChapter`/`closeWindow`), пауза грузовика; нижний бар | `content`, `locale`, `shared/lib`, `shared/ui` |
| `hero` | карточка Hero и её данные (профиль, 3 метрики, CV/Telegram) | `content`, `locale`, `shared/lib`, `shared/ui` |
| `chapters` | тела 8 окон, их блоки (`blocks/`), реестр `WINDOWS` | `content`, `locale`, `route`, `shared/lib`, `shared/ui` |
| `windows` | каркас окна (ChapterWindow, ProofLinks), хост окна, eyebrow и prev/next, история и `#hash`, скрытый текст глав для предрендера | `chapters`, `content`, `locale`, `route`, `shared/lib`, `shared/ui` |
| `fallback2d` | 2D-карта (рендеры острова, хотспоты) | `content`, `locale`, `theme`, `shared/lib`, `shared/ui` |
| `scene` (ленивый) | TresJS-сцена; `index.ts` — ленивая точка входа + лёгкие реэкспорты (`mapRotation`) | `content`, `locale`, `route`, `theme`, `shared/lib` |
| `mode` | режим 3D/2D: `shouldUse3D`, стор режима и состояния сцены, `?mode=`, загрузка сцены с таймаутом, заглушка, баннер, кнопки режима и поворота | `scene`, `locale`, `shared/lib`, `shared/ui` |
| `app` | оболочка: `App.vue` (композиция), TopBar, раскладка overlay/stacked, `head.ts`, `?shot=` | все, кроме `scene` |
| `src/main.ts` | точка входа vite-ssg (`index.html`) | `app`, `locale`, `theme` (+ CSS темы) |

Правила, которые выводятся из таблицы:
- Источник истины — `frontend/scripts/module-graph.mjs` (объект «модуль → зависимости»). `eslint.config.js`
  генерирует из него записи `boundary()`: модулю запрещены импорты модулей вне его списка и глубокие импорты
  (`../<module>/<file>`) разрешённых. Тест границ проверяет: граф ацикличен; каждая папка `src/*` и
  `src/shared/*` есть в графе; имя внутренней подпапки не совпадает с именем модуля; нарушение ловится; импорт
  через `index.ts` чистый.
- three и `@tresjs/*` — только в `scene`; `scene` импортирует только `mode`; динамический `import()` сцены —
  только в `scene/index.ts`, и этот файл статически не импортирует ни `.vue`, ни three.
- `chapters` и `windows` не используют `import()`: окна в главном чанке и в предрендере.
- Раскладка модуля одинакова: `index.ts` (вверху 2–4 строки: что делает, от чего зависит, что экспортирует),
  компоненты `*.vue`, композиции и сторы `use*.ts`, остальное `*.ts`, тесты в `__tests__/`. Подпапки — только
  для групп внутри модуля (`chapters/blocks/`, `scene/buildings/`, `shared/ui/icons/`). Отдельные README и
  CLAUDE.md на модуль не заводим.
- ESLint `max-lines` 250 (без пустых строк и комментариев) для `src/**/*.{ts,vue}`, кроме `__tests__` и
  сгенерированных файлов темы. Спеки — ≤ ~250 строк по соглашению.
- Интеграционные сценарии через `App` лежат в модуле, чьё поведение проверяют
  (`<module>/__tests__/App.<module>.spec.ts`), монтируются общим `app/__tests__/mountApp.ts`. В `src/__tests__/`
  остаются только глобальные инварианты: бандл, предрендер, SEO-ассеты, «только токены».
- Сторы: `theme` — тема; `locale` — язык; `route` — активная остановка, открытое окно, посещённые, пауза
  движения (`openChapter` атомарно ставит всё сразу, D5); `mode` — режим, выбор пользователя, состояние сцены.
  Ключи `localStorage`/`sessionStorage` не меняются: их читает inline-скрипт `theme/boot.ts`.

## Последствия
- Становится проще: задача «поправь бар» читает `src/route/` и его тесты; `App.vue` — композиция модулей без
  своей логики (≤ 250 строк); новая область (телеметрия этапа 4, живые метрики Monitoring — ленивый модуль по
  образцу `scene`) — новая строка графа и новая папка; нарушение архитектуры видно как ошибка линтера.
- Становится сложнее: новая стрелка между модулями — правка графа и таблицы в `frontend/CLAUDE.md` (тест их
  сверяет); барели `index.ts` держим без побочных эффектов; разовая миграция по плану
  `docs/plans/stage-3b-frontend-modules.md`, стартует после T12b.
- Не меняется: поведение, URL, ключи хранилищ, селекторы e2e, контракты контента, бюджеты; ADR-0003 и
  ADR-0005 (сцена по-прежнему одна ленивая папка `src/scene`).
- Итог миграции (M18, 2026-10-24): 13 модулей + корень `main.ts` в графе, переходных записей нет; `App.vue`
  627 → 192 строки (166 по `max-lines`), `App.spec.ts` разнесён по `App.<module>.spec.ts` модулей;
  vitest 696 → 783, e2e 42/42; main-чанк 86.29 → 87.22 КБ gzip.
- Сигнал пересмотреть: модуль перерастает ~15 файлов; стрелки графа приходится добавлять в каждой второй задаче
  (граф выбран неверно); стор одного модуля читают больше трёх модулей (область общая — выделить её);
  фронт переходит на несколько страниц с разными макетами.
