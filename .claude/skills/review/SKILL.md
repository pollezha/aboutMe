# Многоагентное ревью

Схема по мотивам того, как ревьюит команда Claude Code: несколько искателей → проверка находок → человеку только подтверждённое.

## Шаги
1. **Объём.** Определи дифф: `git diff main...HEAD` (или указанный пользователем диапазон). Со 2-го раунда — только дифф с прошлого ревью. Запиши номер раунда; если это 4-й — остановись и предложи пересмотреть подход вместо очередной правки.
2. **Поиск (параллельно).** Запусти сабагентов `reviewer` в чистом контексте, каждому — дифф, REVIEW.md, CLAUDE.md, спеку и один фокус:
   - корректность и граничные случаи;
   - безопасность (вход, авторизация, секреты, инъекции);
   - данные и производительность (транзакции, N+1, индексы, идемпотентность);
   - тесты (покрывают ли поведение, упадут ли без фикса) и соответствие CLAUDE.md.
   Для диффа меньше ~50 строк достаточно одного `reviewer` со всеми фокусами.
   Если дифф меняет то, что видно (`frontend/src/**/*.vue`, стили, токены, сцена, контент), параллельно запусти
   `design-reviewer` на парах кадров `docs/design/compare/` — расхождение с Figma в рамках задачи считается major.
3. **Перепроверка.** Все находки передай сабагенту `verifier`. Он подтверждает или отклоняет каждую по коду, требуя файл:строку и конкретный сценарий сбоя. Отклонённые не показывай.
4. **Дедупликация.** Объедини одинаковые находки; однотипные — в одну с перечнем мест. Убери то, что уже отклонялось в прошлых раундах.
5. **Отчёт:**

```
REVIEW раунд N: 1 blocker, 2 major, 1 minor
[blocker] src/Orders/Handler.cs:42 — повторная доставка события создаёт дубликат заказа.
  Сценарий: консьюмер упал после SaveChanges, сообщение пришло снова.
  Фикс: idempotency key / проверка по EventId.
...
```
   Если чинить нечего — «REVIEW раунд N: 0 замечаний» и всё.
6. **Исправление.** Спроси пользователя, чинить ли всё или выборочно. Однотипные проблемы исправляй пачкой. После правок — `/verify`, затем следующий раунд ревью (только новый дифф).
7. **Учёт.** Если пользователь пометил находку как ложную — запиши причину в отчёт; повторяющиеся ложные срабатывания → предложи уточнить REVIEW.md через `/learn`.

## Дополнительно
- Для отдельного прохода безопасности есть встроенная команда `/security-review`.
- AI-одобрение не заменяет решение человека по рискованным изменениям (миграции, деньги, авторизация, CI).
