# Реализация задачи

Одна задача за раз. Аргумент — id задачи (например `T2`); без аргумента — первая невыполненная задача, у которой выполнены зависимости.

## Цикл
1. **Загрузка контекста.** Прочитай задачу в `docs/plans/`, связанную спеку, CLAUDE.md и только нужные файлы кода. Если задача неясна или противоречит коду — остановись и спроси.
2. **Красный.** Напиши тест на поведение из критерия «готово». Запусти — убедись, что он падает и падает по ожидаемой причине.
3. **Зелёный.** Минимальный код, чтобы тест прошёл. Не трогай то, что не относится к задаче.
4. **Рефакторинг.** Убери дублирование, улучши имена. Тесты зелёные.
5. **Полный прогон.** Сборка + все тесты + линтер. Чинить свои поломки, а не отключать тесты.
6. **Самопроверка диффа** (`git diff`):
   - нет отладочного кода, закомментированных блоков, TODO без задачи;
   - нет секретов и захардкоженных адресов;
   - обработаны ошибки и граничные случаи из спеки;
   - изменения в публичных контрактах есть в ADR.
7. **Коммит.** Conventional Commits: `feat(scope): …`, `fix(scope): …`. Одна задача — один коммит.
8. **Отметка.** Поставь `[x]` у задачи в плане. Коротко сообщи: что сделано, какие тесты добавлены, что дальше.

## Стоп-сигналы
- Тот же тест падает после 3 попыток исправления → переходи в `/debug`, не перебирай варианты вслепую.
- Задача оказалась вдвое больше ожидаемого → предложи разбить её в плане.
- Нужна новая зависимость или смена контракта → спроси пользователя.
