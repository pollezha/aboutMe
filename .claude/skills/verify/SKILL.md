# Самопроверка с доказательствами

Правило: утверждение «работает» без приложенного вывода команды не считается.

## Шаги
1. **Сборка** с нуля (clean build). Ноль ошибок; новые warnings — объяснить или убрать.
2. **Тесты:** весь набор. Приложи итоговую строку (passed/failed/skipped). Пропущенные тесты — перечислить с причиной.
3. **Статический анализ:** линтер, форматтер в режиме проверки, анализатор типов — что есть в проекте.
4. **Запуск.** Подними приложение с зависимостями (docker compose / dev-сервер). Проверь health check.
5. **Сценарии приёмки.** По каждому AC из спеки выполни реальную проверку:
   - API — запрос curl/httpie и фактический ответ;
   - UI — Playwright или скриншот;
   - события/очереди — сообщение действительно опубликовано и обработано (лог/консьюмер).
6. **Негативные сценарии:** невалидный ввод, отсутствие авторизации, недоступная зависимость — система ведёт себя предсказуемо.
7. **Отчёт** в формате:

```
VERIFY: PASS | FAIL
Сборка: ok
Тесты: 142 passed, 0 failed, 1 skipped (причина: …)
Линтер: ok
AC1 ✅ <команда> → <результат>
AC2 ❌ <что пошло не так>
Негативные: …
```

При FAIL — не чинить молча в этом же скилле: перечисли проблемы и предложи `/implement` или `/debug`.
