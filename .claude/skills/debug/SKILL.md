# Систематическая отладка

Запрещено: менять код наугад, пока причина не подтверждена.

## Шаги
1. **Симптом.** Запиши точно: ожидалось / получилось / где / с какими данными. Собери стектрейс, логи, версию.
2. **Воспроизведение.** Добейся стабильного воспроизведения — лучше всего падающим автотестом. Не воспроизводится → собирай больше данных (логи, состояние БД), а не гадай.
3. **Сужение.** Найди минимальный входной случай. Бинарный поиск по коду или истории (`git bisect`), если раньше работало.
4. **Гипотезы.** Выпиши 2–4 гипотезы, отсортированные по вероятности. Для каждой — эксперимент, который её подтвердит или опровергнет (лог, точка останова, изолированный тест). Проверяй по одной.
5. **Корневая причина.** Сформулируй одним предложением: «X происходит, потому что Y». Спроси «почему» ещё раз — не симптом ли это более глубокой проблемы?
6. **Исправление.** Регрессионный тест уже есть с шага 2 → минимальный фикс → тест зелёный → весь набор зелёный.
7. **Похожие места.** Поищи тот же паттерн ошибки в остальном коде (grep) и сообщи о найденном.
8. **Урок.** Если баг мог быть пойман раньше — предложи `/learn` (правило в REVIEW.md, тест, линтер).

После 3 опровергнутых гипотез — остановись, перечисли, что проверено, и обсуди с пользователем.
