# Спецификация через интервью

Цель — до начала кода получить `docs/spec/<feature-slug>.md` по шаблону `docs/spec/_template.md`, который пользователь явно одобрил.

## Шаги

1. **Контекст.** Прочитай CLAUDE.md, существующие спеки в `docs/spec/` и `docs/learnings.md`. Бегло посмотри код в зоне фичи. Не задавай вопросов, ответ на которые есть в репозитории.
2. **Интервью.** Задавай вопросы порциями по 2–4, от главного к деталям:
   - кто пользователь и какую боль решаем;
   - главный сценарий от начала до конца;
   - что НЕ входит в объём;
   - ограничения: данные, производительность, безопасность, внешние системы;
   - как поймём, что готово (критерии приёмки).
   На каждый вопрос предлагай свой вариант ответа по умолчанию — пользователь может просто согласиться.
3. **Альтернативы.** Если есть 2+ принципиально разных способа решить проблему, коротко покажи их с трейдоффами и рекомендацией.
4. **Черновик.** Заполни шаблон. Каждый критерий приёмки — в форме «Дано / Когда / Тогда» и проверяем тестом или ручным шагом.
5. **Самопроверка черновика:**
   - нет требований без критерия приёмки;
   - нет расплывчатых слов («быстро», «удобно») без числа или примера;
   - не-цели явно перечислены;
   - открытые вопросы вынесены отдельно, а не спрятаны в тексте.
6. **Одобрение.** Покажи краткое резюме (5–7 строк) и спроси, утверждаем ли. После «да» поставь `Статус: approved`.

## Дальше
- Если решение затрагивает структуру системы, контракты или выбор технологий → предложи `/architecture`.
- Иначе → `/plan`.
